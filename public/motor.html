O Motor de Cadência por Lote Real

Como o motor funciona, os arquivos, a superfície de controle e como validar. Para o Nando e o Claude dele.

1. Visão geral 2. Arquitetura 3. As fases 4. Os relógios 5. turma_lotes 6. Controlar 7. Travas 8. Validar

1. Visão geral

O motor conduz o follow-up 100% automático dos leads que esfriaram, ancorado no lote real da turma.

Cada turma tem seus lotes reais (tabela turma_lotes: preço + data de virada). O motor calcula, pela data de hoje, o lote vigente e a fase da turma — e disso saem o preço da mensagem, a urgência e a coluna do board.

Guarda de ouro: turma sem lote cadastrado = comportamento antigo intacto. O modelo novo só age em turma com lote. Zero risco para o resto.

3. As fases do motor (o que cada uma faz)

Tudo dentro do followup-auto, em camadas guardadas por dv (dias até a virada).

CamadaQuandoO quê
Preço realsempre (turma c/ lote)Preço da mensagem = loteVigente.preco_pix + parcela real.
Reposiçãodv > 3, qualquer etapa ativa1× por lead: avisa a data certa. cnd_reposicao_unico (lote único) ou cnd_reposicao_lote (multi-lote).
Nutriçãodv > 3, pós-preçoGoteja cnd_nutri_1..8 (cases), 1 a cada ~3 dias, cada 1×.
Urgênciadv 1–3cnd_lote_virando ("está encerrando"). Vale em qualquer etapa ativa.
Último diadv ≤ 0cnd_lote_ultimo ("hoje é o último dia").
Board por faseUIToggle no CRM: colunas = fase da turma; etapa vira tag; drag desligado.
Prioridade no loop: urgência (dv≤3) → reposição → nutrição → cadência normal. Como urgência é dv≤3 e reposição/nutrição são dv>3, nunca colidem.

4. Os dois relógios

Relógio A — chegada (por lead)

Reativo: ligação → puxa WhatsApp → apresentação (com preço/data reais). Conta da entrada na etapa.

Relógio B — turma (por data real)

dv = diasAteVirada(lotes, hoje) e fase = faseTurma(lotes, dataInicio, hoje). É o que dispara reposição/nutrição/urgência e posiciona o card no board. Converge todos da turma na mesma data.

// fases, da mais longe à mais perto da turma
vendas_abertas → lote_avancado → ultimo_lote → vespera → encerrada

5. Cadastrar uma turma nova (o que mantém tudo vivo)

Cadastrou a turma + os lotes → o motor assume sozinho. Sem lote = modo antigo.

Cada linha de turma_lotes:

{ turma_id, ordem, nome, preco_pix, preco_cartao, parcela_cartao, vale_ate }
  • ordem: 1, 2, 3… (lote 1 é o mais barato)
  • vale_ate: a data real em que esse lote fecha (YYYY-MM-DD)
  • Lote único (sem virada de preço): 1 linha só — o vale_ate é o início da turma
O lote vigente = o de menor ordem cujo vale_ate ainda não passou. Passaram todos → o último. A reposição escolhe "estendi o lote 1" (se há próximo lote) ou "segurei o valor" (lote único) sozinha.

6. Superfície de controle

Tudo tem dryRun. Base: https://carreiranodigital.vercel.app

Ver o que o motor FARIA (não envia)

POST /api/ia/followup-auto
{ "dryRun": true, "limit": 400 }

// retorna: resumo { envio_real, vai_pro_time, vira_perda, pulado_sem_preco }
// + amostra das mensagens renderizadas

Enviar de verdade (lote de até 60, mais frio primeiro)

POST /api/ia/followup-auto
{ "dryRun": false, "confirm": true, "limit": 60 }

Kill switch — ligar/desligar TODOS os envios

POST /api/ia/ia-automacao
{ "ligado": false }   // desliga · { "ligado": true } religa

Fase de cada turma (o board consome)

GET /api/turmas/fases   // { fases: { turma_id: "ultimo_lote", ... } }

Submeter templates novos à Meta

// 1) inserir em followup_templates (status='rascunho')
// 2) submeter:
POST /api/wa-oficial/criar-templates
{ "ids": ["<id1>", "<id2>"] }
// aprovação sincroniza ao abrir a tela de Templates (só 'aprovado' dispara)
O orquestrador cron-run?fase=manha roda a sequência da manhã (warming → virada de ontem → reconciliar → followup → posse-funil → garantir-tarefas → roteador → sem-cidade-perda → sync-pool). fase=noite roda a virada (quem respondeu) + sync-pool.

7. Travas de segurança

  • Preço R$0 / inventado → aborta o envio.
  • Prazo no passado (data que já venceu) → não envia.
  • Template não aprovado na Meta → nem tenta (só status='aprovado').
  • Não repete o mesmo template em 14 dias (checa lead_andamentos).
  • Engajado recente (24h) → é do time, motor não toca.
  • Não rebaixa etapa, não re-apresenta quem já viu o pitch.
  • Máximo 1 mensagem por lead por dia.
  • Cooldown de 7 dias pós-reativação do roteador.
Se responder, é do time. O lead que responde sai da automação e volta pro humano (via webhook). A IA só cuida do frio.

8. Validar no dia a dia (Nando)

  1. DryRun do motor de manhã → conferir resumo (pulado_sem_preco tem que ser 0) e ler a amostra (nome, preço e data certos).
  2. CRM → 📅 Por fase → agosto em Último lote/Véspera, setembro em Vendas abertas; ninguém quente sumiu.
  3. Abrir 2–3 leads tocados hoje → ver no histórico a mensagem certa, no momento certo, com o preço do lote certo.

Sinais de saúde: pulado_sem_preco = 0 · reposição 1× por lead · nutrição espaçada · urgência só perto da virada · quem respondeu virou "humano".

Parar tudo: kill switch { "ligado": false }. Um lead errado: abra o card, veja os andamentos, chame o Claude com o nome + o esperado.

Pendências que dependem de decisão (não são bug): cnd_nova_turma (roteador) aguardando Meta; turmas sem próxima turma cadastrada. Próximo passo do SaaS: motor role-driven / por-org — a cadência deixa de ser código e vira dado da turma/cliente.
